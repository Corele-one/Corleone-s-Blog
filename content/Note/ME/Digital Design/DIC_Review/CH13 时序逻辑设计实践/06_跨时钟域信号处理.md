# 06 跨时钟域信号处理

跨时钟域 CDC 指信号从一个时钟域进入另一个时钟域，或外部异步信号进入同步系统。由于发送端和接收端采样边沿没有固定相位关系，信号可能在接收时钟边沿附近变化，从而引发亚稳态 metastability。

## 亚稳态

亚稳态是触发器输入违反 setup/hold 要求后可能出现的中间状态。触发器输出既不是可靠的 0，也不是可靠的 1，并且恢复到稳定值所需时间不确定。

特点：

- 无法完全消除。
- 可以通过同步器降低传播到系统中的概率。
- 不能把第一级可能亚稳态的输出直接送入大量后级逻辑。

## 单比特信号：两级同步器

推荐做法是使用两个同一接收时钟域内串联的触发器：

![[file-20260702103414723.png|617x206]]

```text
ASYNCIN -> FF1 -> META -> FF2 -> SYNCIN -> 同步系统
             ^      ^
             |      |
          同一接收时钟 CLOCK
```

作用：

- FF1 负责采样异步输入，可能进入亚稳态。
- FF2 给 FF1 一个时钟周期恢复。
- 同步系统只使用 FF2 输出 `SYNCIN`。

## 同一异步输入不要用多个同步器分别采样

如果同一个异步输入同时进入多个同步器，不同同步器可能在不同周期采到变化，导致后级逻辑看到互相矛盾的状态。

![[file-20260702103459747.png|539]]


正确思路：

- 异步输入先进入一个同步器。
- 后级所有同步逻辑都使用同步器输出。

## 多比特数据跨域

多比特总线不能简单逐位加两级同步器，因为各位可能在不同接收周期稳定，形成错误编码。

常用处理方法：

- 数据保持稳定 + `valid/ready` 握手。
- 请求/应答 handshake。
- Gray code 计数器：相邻值只改变一位，常用于 FIFO 指针。
- 异步 FIFO：写端和读端各自使用不同的时钟。

## 异步 FIFO

![[file-20260702103557738.png|591]]

异步 FIFO 适合**两个不同频率**或**不同相位的时钟域**之间**传输连续数据流**。

基本结构：

- 写端属于 clock domain A，使用写时钟 `CLKA`。
- 读端属于 clock domain B，使用读时钟 `CLKB`。
- FIFO 内部存储数据。
- 读写指针跨域同步，用于判断 empty/full。


## 学习要点

- 单比特慢变化控制信号：两级同步器。
- 单比特脉冲：加宽、toggle 或握手。
- 多比特控制编码：优先 Gray code 或握手。
- 多比特连续数据流：异步 FIFO。
- CDC 问题本质上不是功能逻辑问题，而是采样时刻不确定造成的可靠性问题。
