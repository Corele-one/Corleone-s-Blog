# 二义性状态（Ambiguous State）

## 一、什么是二义性状态？

> **核心定义**：当一个状态机的状态图中，某个状态的**出边转移表达式**不满足**互斥性**和/或**完备性**时，该状态被称为**二义性状态（Ambiguous State）**。

判断一个状态图是否无二义性，需要对**每一个状态**检查两条性质：

### 1. 互斥性（Mutual Exclusion）

> 对于每一个状态，离开该状态的**任意一对**转移表达式的逻辑积（AND）等于 0。

即：**不可能同时满足两个不同的转移条件**。如果 n 条出边，需要验证 C(n,2) = n(n-1)/2 次两两配对。

### 2. 完备性（All Inclusion / Completeness）

> 对于每一个状态，离开该状态的**所有**转移表达式的逻辑积之和（OR）等于 1。

即：**所有可能的输入组合都能触发某一条转移**，不存在"不知道该走哪条路"的输入情况。

### 3. 直观理解

| 检验项 | 要求 | 不满足时的后果 |
|--------|------|--------------|
| **互斥性** | 每个输入组合**最多**触发一条转移 | 同一输入可以走两条路→"不知走哪条" |
| **完备性** | 每个输入组合**至少**触发一条转移 | 某些输入无路可走→"机器卡死" |
| **两者都满足** | 每个输入组合**恰好**触发一条转移 | ✅ 无二义性 |

## 二、经典案例：雷鸟车尾灯状态机

### 2.1 问题背景

1965 年福特雷鸟车尾灯控制：
- 车尾每边 3 个灯（LA/LB/LC 和 RA/RB/RC）
- 左转：左边 3 灯依次亮起；右转：右边 3 灯依次亮起
- 告警（HAZ）：所有 6 灯同时闪烁
- 输入信号：LEFT、RIGHT、HAZ

### 2.2 初始状态图（存在二义性）

![[file-20260704235515560.png]]

**输出表：**

| 状态 | LC | LB | LA | RA | RB | RC |
|------|----|----|----|----|----|-----|
| IDLE | 0 | 0 | 0 | 0 | 0 | 0 |
| L1 | 0 | 0 | 1 | 0 | 0 | 0 |
| L2 | 0 | 1 | 1 | 0 | 0 | 0 |
| L3 | 1 | 1 | 1 | 0 | 0 | 0 |
| R1 | 0 | 0 | 0 | 1 | 0 | 0 |
| R2 | 0 | 0 | 0 | 1 | 1 | 0 |
| R3 | 0 | 0 | 0 | 1 | 1 | 1 |
| LR3 | 1 | 1 | 1 | 1 | 1 | 1 |

**输出方程：**
$$LA = L1 + L2 + L3 + LR3 \qquad RA = R1 + R2 + R3 + LR3$$
$$LB = L2 + L3 + LR3 \qquad\qquad RB = R2 + R3 + LR3$$
$$LC = L3 + LR3 \qquad\qquad\quad RC = R3 + LR3$$

### 2.3 IDLE 状态的二义性分析

在初始状态图中，从 IDLE 出发的转移条件为：

| 目标状态 | 转移条件 |
|---------|---------|
| L1 | LEFT |
| R1 | RIGHT |
| LR3 | HAZ |

**互斥性验证（3条边 → C(3,2) = 3 次验证）：**
- LEFT · RIGHT = ? → 当 LEFT=1, RIGHT=1 时为 1 ❌
- LEFT · HAZ = ? → 当 LEFT=1, HAZ=1 时为 1 ❌
- RIGHT · HAZ = ? → 当 RIGHT=1, HAZ=1 时为 1 ❌

**完备性验证：**
- LEFT + RIGHT + HAZ = ? → 当三者都为 0 时为 0 ❌

> ⚠️ IDLE 状态**既不满足互斥性，也不满足完备性**，是典型的二义性状态。
> 例如：当 LEFT=1 且 HAZ=1 时，机器不知道该进入 L1 还是 LR3。

### 2.4 修正后的状态图（无二义性）

![[file-20260704235538810.png]]

修正策略：**给 HAZ 最高优先级，且将 LEFT+RIGHT 同时有效视为告警**

| 目标状态 | 转移条件 |
|---------|---------|
| L1 | LEFT · HAZ' · RIGHT' |
| R1 | RIGHT · HAZ' · LEFT' |
| LR3 | HAZ + LEFT · RIGHT |
| IDLE（自环） | (LEFT + RIGHT + HAZ)' |

**验证 IDLE 状态：**

互斥性（C(4,2) = 6 次）：
- (LEFT·HAZ'·RIGHT') · (RIGHT·HAZ'·LEFT') = 0 ✅
- (LEFT·HAZ'·RIGHT') · (HAZ + LEFT·RIGHT) = 0 ✅
- (LEFT·HAZ'·RIGHT') · (LEFT+RIGHT+HAZ)' = 0 ✅
- (RIGHT·HAZ'·LEFT') · (HAZ + LEFT·RIGHT) = 0 ✅
- (RIGHT·HAZ'·LEFT') · (LEFT+RIGHT+HAZ)' = 0 ✅
- (HAZ + LEFT·RIGHT) · (LEFT+RIGHT+HAZ)' = 0 ✅

完备性：
$$\text{LEFT·HAZ'·RIGHT'} + \text{RIGHT·HAZ'·LEFT'} + \text{HAZ + LEFT·RIGHT} + \text{(LEFT+RIGHT+HAZ)'} = 1 \quad ✅$$

## 三、例题精讲

### 题目

> Fig. 4 所示的状态图有（ **B. 2** ）个二义性状态。

![[file-20260704234814470.png|688]]

输入变量为 X、Y，逐个检查每个状态出边的**互斥性**和**完备性**。

### 逐状态验证

| 状态 | 出边条件 | 互斥性 | 完备性 | 结论 |
|------|---------|--------|--------|------|
| **A** | Y, Y' | Y·Y'=0 ✅ | Y+Y'=1 ✅ | 无二义 |
| **B** | X', XY', XY | 两两积=0 ✅ | X'+XY'+XY=1 ✅ | 无二义 |
| **C** | X, Z | X·Z 可≠0 ❌ | X+Z 可≠0 ❌ | ⚠️ 二义 |
| **D** | X, Y | X·Y=1 当(1,1) ❌ | X+Y=0 当(0,0) ❌ | ⚠️ 二义 |

> ⚠️ 状态 C 的自环标记为 Z（非 X 的表达式），当 X=1,Z=1 时互斥性不满足；当 X=0,Z=0 时完备性不满足。

### ✅ 最终答案：**B. 2**（二义性状态为 C 和 D）

## 四、总结

```
判断二义性状态的口诀：
    互斥：两两 AND 必须为 0（不能同时走两条路）
    完备：所有 OR 必须为 1（不能无路可走）
    二者缺一 → 二义性状态
```

**设计无二义性状态机的关键原则：**
1. **优先级机制**：如雷鸟例子中 HAZ 优先于 LEFT/RIGHT
2. **互斥编码**：转移条件设计时确保互斥
3. **完备覆盖**：确保所有输入组合都有对应转移
4. **兜底状态**：用 `default` 或 `(条件1+条件2+...)'` 作为默认转移
