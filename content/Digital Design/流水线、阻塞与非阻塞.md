## 流水线
### 频率越高是否就意味着流水线的级数要更高？
在时钟频率高的时候，可以隔两个时钟再来采一次数据，就可以在长路径的寄存器的对应时钟路径上插入缓冲器，使用缓冲器来减少延迟间的差异，==waveform pipeline design==

### Waveform Pipeline Design（波形流水线 / 波动流水线）
#### 核心思想
传统流水线（synchronous pipeline）在每一级组合逻辑之间都插入寄存器，每个时钟周期完成一级运算；而 **waveform pipeline** 不增加中间寄存器，而是允许 **多个"数据波"同时在同一段组合逻辑中传播**。利用组合路径的传播延迟本身作为"虚拟流水线级"，在源端每个时钟发射一个数据波，在终点按对应时钟相位采样。

简单来说：
- 普通流水线：用**寄存器**把长路径切短。
- 波形流水线：不切路径，而是让**多份数据像水波一样在路径上同时传播**，靠时钟相位区分先后。

#### 关键时序条件
设组合路径最大延迟为 $T_{max}$、最小延迟为 $T_{min}$，时钟周期为 $T_{clk}$，则：

$$T_{max} - T_{min} < T_{clk} - (t_{setup} + t_{hold} + t_{skew})$$

也就是说，**决定能否做波形流水线的，是路径的 max/min 延迟差（delay spread），而不是 max 延迟本身**。
- 传统流水线限制：$T_{clk} \geq T_{max} + t_{setup} + t_{skew}$
- 波形流水线限制：$T_{clk} \geq (T_{max} - T_{min}) + t_{setup} + t_{hold} + t_{skew}$

只要把 path 的 min/max 延迟做得足够"齐"（差异小），$T_{clk}$ 可以远小于 $T_{max}$，从而**在不增加寄存器、不增加 latency-stage 的情况下提高时钟频率**。

#### 实现要点
1. **延迟均衡（delay matching）**：在快路径上插入 buffer，使所有路径的延迟尽量接近，压缩 $(T_{max} - T_{min})$。这就是上面提到的"在长路径的寄存器对应时钟路径上插入缓冲器"的本质。
2. **采样时钟相位调整**：终点寄存器的时钟需要一个可控的相位偏移（skew / delayed clock），保证采样点正好落在对应的数据波稳定窗口内。
3. **PVT 敏感**：因为依赖具体延迟值，对工艺、电压、温度变化极其敏感，常需要可调延迟线 + 校准电路。
#### 与传统流水线的对比

| 维度 | 传统 Pipeline | Waveform Pipeline |
|---|---|---|
| 中间寄存器 | 多 | 无 / 极少 |
| 面积 | 大 | 小 |
| Latency（流水级数） | 高 | 低 |
| 频率上限取决于 | $T_{max}$ | $T_{max} - T_{min}$ |
| PVT 鲁棒性 | 好 | 差，需校准 |
| 设计复杂度 | 低 | 高（要做延迟均衡和相位调整） |

#### 适用场景
- 高速专用通路：DSP、加法/乘法阵列、SerDes、Cache 访问路径等延迟可控、结构规整的电路。
- 不适合：控制密集、路径分支多、延迟难以均衡的逻辑。

#### 一句话总结
Waveform pipeline 是一种"用延迟线代替寄存器"的流水线技巧——它把传统流水线"在路径中切寄存器"换成了"在路径上让多个数据波同时跑"，吃的是延迟均匀度，而不是延迟绝对值。

#### 设计哲学：用工程手段解决工程问题
==纹波流水线本质上是一种"用工程手段解决工程问题"的方法==。它没有提出新的逻辑结构，也没有改写算法，只是承认一个工程现实——**寄存器是有代价的（面积、功耗、latency）**——然后用一组可控的物理延迟（buffer、延迟线、时钟相位）去把这部分代价换出来。

这种思路体现了几点典型的数字 IC 工程观：
- **不去消灭问题，而是驯服问题**：长路径延迟无法消灭，那就让它"按节拍可控地跑"。
- **把不确定性变成可设计的参数**：传统 STA 把 $T_{max}-T_{min}$ 当成被动余量，波形流水线把它当成主动设计变量去压。
- **PPA 三角的位置交换**：传统流水线是"加面积换频率"，波形流水线是"加延迟均衡 + 校准电路换面积和 latency"，本质都是在 Performance / Power / Area 三角里换位置。
- **代价是鲁棒性**：所有"工程取巧"都要付学费——这里付的是 PVT 敏感性和校准复杂度。这也是为什么它只在结构规整、延迟可控的局部路径上用，而不会成为通用方法。

换句话说，它不是一种"更聪明的算法"，而是对物理时序的**精细化操盘**——这是数字 IC 设计里典型的工程美学：**承认物理约束，并把它变成自己的工具**。
