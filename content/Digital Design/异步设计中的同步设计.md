## 平均错误发生间隔
MTBF(Mean Time Between Failure)
![[file-20260526113448515.png|728x130]]
$t_r$相当于是一个时序的裕度，$t_{r}$越大，发生亚稳态的概率越低
![[file-20260526113545858.png|185x57]]
如果想要增加MTBF的话，从公式上看可以：
1. 降低组合逻辑的延时，在同步线之间做两级流水线，做成两级同步器，中间用线相连，相当于是最短的组合逻辑路径
2. 降频，增加时钟间隔/变相降频(即纹波流水线)

### 两级同步器（Two-Flop Synchronizer）详解
#### 为什么单级寄存器不够？
异步信号到达时，跳变沿可能正好落在目标时钟域寄存器的 setup/hold 窗口内，导致输出 Q **进入亚稳态**——既不是稳定的 0 也不是稳定的 1，而是在某个不确定电压上"晃荡"。这个晃荡过程是个**随机指数衰减**：经过时间 $t$ 后仍未稳定的概率约为 $e^{-t/\tau}$，其中 $\tau$ 是寄存器的"亚稳态时间常数"，由工艺决定。

如果只用一级寄存器，下游组合逻辑直接接它的 Q 端，那么：
- Q 还没稳定的时候就会被组合逻辑读到。
- 不同 fanout 路径可能把"还没稳"的 Q 当成不同的逻辑值，引发**逻辑发散**（同一个信号在电路里不同地方被解读成 0 和 1，整个状态机就乱了）。

#### 两级同步器在做什么？
结构非常简单，就是**两个 D 触发器串联，中间不放任何组合逻辑**：

```
async_in ──▶ [DFF1] ──▶ [DFF2] ──▶ sync_out
              │           │
              └─clk_dst───┘   (同一时钟域)
```

工作过程：
- **第 1 拍**：DFF1 采样异步信号，可能进入亚稳态。
- **DFF1 → DFF2 之间的这个时钟周期**：留给 DFF1 的输出"自己慢慢稳定下来"。这段时间就是公式里的 $t_r$（resolution time，解决时间），是 DFF1 用来从亚稳态衰减到稳定逻辑值的时间窗口。
- **第 2 拍**：DFF2 采样 DFF1 已稳定的输出，输出一个干净的逻辑值给后级使用。

> 关键点：**中间用线直接相连，没有任何组合逻辑**。这样 DFF1 → DFF2 的路径延迟最短，留给亚稳态衰减的时间 $t_r$ 几乎等于一整个 $T_{clk}$。

#### 为什么这能增加 MTBF？
回到 MTBF 公式（典型形式）：

$$\text{MTBF} = \frac{e^{t_r / \tau}}{T_{win} \cdot f_{clk} \cdot f_{data}}$$

其中：
- $t_r$：留给亚稳态衰减的时间
- $\tau$：寄存器的亚稳态时间常数（工艺给定）
- $T_{win}$：寄存器对异步沿敏感的时间窗（亚稳态触发窗口）
- $f_{clk}$：目标时钟频率
- $f_{data}$：异步信号跳变速率

==MTBF 是 $t_r$ 的指数函数==，所以 $t_r$ 多一拍，MTBF 直接指数级提升。

- **单级**：$t_r = T_{clk} - t_{comb} - t_{setup}$（要给后面组合逻辑留路径延迟），可能只剩半个周期甚至更少。
- **两级**：第一级到第二级中间没有组合逻辑，$t_r \approx T_{clk} - t_{setup}$，几乎榨干一整个时钟周期。

举个直观数字：假设 $\tau = 100\,\text{ps}$，$T_{clk} = 1\,\text{ns}$。
- 若单级 $t_r = 0.3\,\text{ns}$，则 $e^{t_r/\tau} = e^3 \approx 20$。
- 若两级 $t_r = 0.9\,\text{ns}$，则 $e^{t_r/\tau} = e^9 \approx 8100$。

**只是多加一个寄存器，MTBF 提升了 ~400 倍**——这就是为什么"中间用线相连，相当于最短的组合逻辑路径"那么关键。

#### 这里"两级流水线"和普通流水线的区别
你笔记里说的"两级流水线"容易误解，它**不是为了切割长路径提高频率**，而是：
- 普通 pipeline：每级之间塞组合逻辑，目的是"切短路径"。
- 两级同步器：每级之间**故意不塞任何东西**，目的是"留出整整一个周期让亚稳态衰减"。

可以理解成：**它是流水线结构，但用法是反的**——==用一整级寄存器换"等一整个周期"的时间预算==

#### 设计要点
1. **中间不能有任何组合逻辑或 fanout 分叉**：否则会破坏"DFF1 的输出还没稳就被读走"的隔离效果。
2. **两级 DFF 必须在同一个目标时钟域**：用同一个 clk_dst，不能跨域。
3. **只能同步 1-bit 信号**：多 bit 总线不能直接两级同步——不同 bit 落入亚稳态的概率独立，会导致**多 bit 不一致**（比如 0111 → 1000 这种跳变中间可能采到任意中间值）。多 bit 跨域要用 **格雷码（Gray code）+ 两级同步器**，或者 **异步 FIFO**。
4. **更高 MTBF 需求**：可以做三级同步器，但只在极高频率或极敏感场景才需要——每多一级换一个数量级，但 latency 也多一拍。
5. **建议加综合约束**：通常用 `set_false_path` 或专用的 ASYNC_REG 属性告诉工具"这条路径是异步的，不要做时序检查，但要保证两个 FF 物理上挨着放"。

#### 一句话总结
两级同步器不是"普通的两级流水线"，而是==用一整个时钟周期作为亚稳态衰减的缓冲区==，把 $t_r$ 拉到接近 $T_{clk}$，从而让 MTBF 在指数项上获得几个数量级的提升。

## 多打几拍实现同步

应用情况:两个时钟差不多是同频的

### 多打几拍同步中的相位问题
"多打几拍"指的是源时钟域的信号送到目的时钟域之后，==连续打几个目的时钟域的寄存器==（通常是 2~3 级），用多采样几次的方式让信号在目的时钟域稳定下来。它适用的前提是：**两个时钟同频或近似同频，但相位关系不固定（同频异相）**——比如同一个 PLL 出来分发到两块的 clk，频率一样但布线长度不同导致相位漂。

#### 为什么相位是关键？
两个时钟"频率一样但相位漂移不定"，意味着源域寄存器的 launch edge 和目的域寄存器的 capture edge 之间的**相对时间差是变化的**。这个相对时间差直接决定了：
- 数据从源域 launch 到目的域 FF 的 D 端时，留给目的 FF 的 setup 时间是多少；
- 是否会撞进目的 FF 的 setup/hold 窗口，从而触发亚稳态。

对应的关键参数：

$$t_{slack} = T_{clk} - \phi_{drift} - t_{co} - t_{wire} - t_{setup}$$

其中 $\phi_{drift}$ 是两个时钟的相位漂移。如果 $\phi_{drift}$ 大到把 $t_{slack}$ 吃成负数，目的 FF 就会采到正在跳变的 D，进入亚稳态。

#### 问题的本质
==多打几拍并不能消除亚稳态触发的概率==，它做的事情是：
- 让源数据在目的域被采样后，**有足够多的时钟周期去稳定**（每多一级 ≈ 多一个 $T_{clk}$ 的 $t_r$，MTBF 指数级上涨）；
- 让逻辑发散被"封锁"在前几级寄存器内部，下游用最后一级的输出。

但它没有保证：
- 第一级寄存器**采到的数据是哪一拍**——可能采到这一拍，也可能采到下一拍，因为相位漂移会让 setup 边界前后摇摆。

所以"相位出问题"通常不是亚稳态本身的问题（那是 MTBF 来管的），而是**==采样拍数不确定==**带来的两个具体问题。

#### 相位漂移会导致的具体问题
**1. 数据被采几次不固定（duration 漂移）**
源域发出一个持续 N 拍的脉冲，目的域因为相位关系不同，可能采到 N-1 拍、N 拍或 N+1 拍。如果下游用电平触发，没问题；如果下游用沿/计数，就会少计或多计。

**2. 多 bit 之间的相对相位错乱（skew 不一致）**
多根信号从源域过来，每根线的 wire delay 略有不同，加上时钟相位漂移，每个 bit 在目的域被采样的"那一拍"可能不一致——0111 这种跳变可能在过渡瞬间被采成 0011 或 0101。==这是多打几拍最大的相位陷阱==。

**3. 单脉冲被吞掉（pulse swallow）**
如果源时钟比目的时钟略快，或源域脉冲只持续 1 拍，相位漂到不利位置时目的域可能根本采不到这个脉冲。反过来若目的快于源，又可能把同一个脉冲采到两次。

#### 怎么保证相位不出问题
对应上面三类问题，有不同的对策：

**对策 1：保证源信号的持续时间 ≥ 目的时钟的 1.5~2 个周期**

让源域信号在目的域至少跨过 1 个完整的 capture edge，无论相位怎么漂，都至少能采到一次稳定值。
- 实操：在源域用一个寄存器把脉冲展宽（pulse stretcher），或者用握手协议（req/ack）保证源端 hold 住直到 ack 回来。

**对策 2：多 bit 用格雷码 + 两级同步器**

格雷码相邻状态==只变 1 bit==，即使各 bit 相位错乱，最坏情况下也只可能采到"前一个值"或"后一个值"，绝不会采到中间错值。
- 典型应用：异步 FIFO 的读/写指针、跨域计数器。

**对策 3：用握手协议（req/ack 4-phase 或 2-phase）**

源域发出 req 后保持数据稳定，等目的域同步 req → 锁存数据 → 回 ack；源域同步 ack 后才能发下一个。
- 优点：完全规避相位问题，相位漂多少都能正确传输。
- 缺点：吞吐率低，每次传输要走一来一回。

**对策 4：用异步 FIFO**

多 bit + 高吞吐场景下，握手太慢，就上异步 FIFO：
- 数据本身用源时钟写入 RAM；
- 读写指针用格雷码 + 两级同步器跨域；
- 用同步过去的指针生成 full / empty 信号。
- 这是工业上最稳妥的多 bit 跨域方案，相位问题被彻底封装在 FIFO 内部。

**对策 5：在源端加"沿展宽"或"边沿检测同步器"**(用下降沿来采集)

如果只是要传一个事件（脉冲沿），可以：
- 源域用 toggle FF 把脉冲变成电平翻转；
- 目的域两级同步器同步这个电平；
- 在目的域对同步后的电平做==边沿检测还原成脉冲==（pulse synchronizer）。
- 这样既不依赖脉冲宽度，也不需要握手。

#### 总结
| 场景 | 推荐方案 |
|---|---|
| 单 bit 电平 / 慢变信号 | 两级同步器 + 源端展宽 |
| 单 bit 脉冲 / 事件 | Pulse synchronizer（toggle + 同步 + 边沿检测） |
| 多 bit 关联数据，低吞吐 | Req/Ack 握手 |
| 多 bit 高吞吐 / 计数器 | 格雷码 + 两级同步器 / 异步 FIFO |

==核心原则==：**不要试图"赌相位"**——任何依赖两个时钟相位关系稳定的设计在跨时钟域时都是错的。要么靠拍宽冗余（让信号持续够长），要么靠协议（握手 / FIFO），要么靠编码（格雷码），把"相位漂移"这个不确定量从"会不会出问题"变成"出了也无所谓"。
