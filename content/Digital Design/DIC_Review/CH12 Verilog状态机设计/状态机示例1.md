# Ex.1 

![[file-20260630233922729.png]]

```verilog
module FSM1(CLK,RST,A,B,Z);
	input CLK,RST;//时钟和复位信号
	input A,B;
	output reg Z;
	//5个状态，要3bit才能编码
	parameter [2:0] INIT=3'b000,
					A0  =3'b001;
					A1  =3'b010;
					OK0 =3'b011;
					OK1 =3'b100;
	reg [2:0] Sreg,S_next;//状态寄存器和次态的命名
	//第一部分：状态存储器
	always @(posedge CLK) begin
		if(RST)
			Sreg<=INIT;//复位时回到初始状态
		else
			Sreg<=S_next;//正常工作锁存次态
	end
	//第二部分:次态转移逻辑
	//敏感信号列表里为状态和输入信号
	//纯组合逻辑，根据当前状态输出次态
	always@(A,B,Sreg) begin
		//然后根据状态转移表编写转移代码
		case(Sreg)
			INIT:begin
				if(A==0)
					S_next<=A0;
				else
					S_next<=A1;
			end
			A0:begin
				if(A==0)
					S_next<=OK0;
				else
					S_next<=A1;
			end
			A1:begin
				if(A==0)
					S_next<=A0;
				else
					S_next<=OK1;
			end
			OK0:begin
				if(A==0)
					S_next<=OK0;
				else if((A==1)&&(B==1))
					S_next<=OK1;
				else
					S_next<=A1;
			end
			OK1:begin
				if(A==1)
					S_next<=OK1;
				else if((A==0)&&(B==0))
					S_next<=A0;
				else
					S_next<=OK0;
			end
			default:S_next<=INIT;//最小风险处理
		endcase
	end
	//输出逻辑
	//敏感信号列表里为状态，暗示这是一个Moore型FSM
	always@(Sreg) begin
		case(Sreg)
			INIT,A0,A1:Z=0;
			OK0,OK1:Z=1;
			default:Z=0;
		endcase
	end
endmodule
```

>[!hint]
>在输出逻辑简单时，如上例，输出也可以用数据流描述，写成
>```verilog
>	assign Z=(Sreg==OK0)||(Sreg==OK1);
>```

# 把状态存储器和次态逻辑结合起来

![[file-20260701095138416.png]]

> [!tip] 为什么合并后可以删掉 else？
> 这里的 `always @(posedge CLK)` 是**时序块**。当某个分支没有对 `Sreg` 赋值时，综合工具会直接利用**触发器天然的保持功能**（即 Q 端连回 D 端），不需要额外的硬件。
> 而如果是在组合逻辑 `always @(*)` 中缺少 else，综合工具无法"自己保持"，就必须推断出一个**锁存器**来保存值——这才是 latch 的来源。
> **判断标准**：敏感信号是时钟边沿（`posedge CLK`）→ 缺 else = 触发器保持；敏感信号是电平（`always @(*)`）→ 缺 else = 锁存器。

# 复位输入

![[file-20260701095939887.png]]
## 同步复位

```verilog
always@(posedge CLK)
	if(RESET==1)
		Sreg<=INIT;
	else
		Sreg<=Snext;
```

## 异步复位

```verilog
always@(posedge CLK or posedge RESET)
	if(RESET==1)
		Sreg<=INIT;
	else
		Sreg<=Snext;
```

# 补充：`Q <= Q` 到底产生什么？

> [!important] `Q = Q` vs `Q <= Q` 在不同上下文中的综合结果完全不同
>
> | 写法 | always 块类型 | 综合结果 | 原因 |
> |------|-------------|---------|------|
> | `Q = Q` 或 缺 else | `always @(*)`（组合逻辑） | **锁存器（latch）** | 组合环路无法自行保持值，必须推断锁存器 |
> | `Q <= Q` 或 缺 else | `always @(posedge CLK)`（时序逻辑） | **触发器保持** | FF 天然在每个时钟沿保持，Q 端连回 D 端即可 |
>
> - 在 `always @(*)` 中，`Q = Q` 或 if 缺少 else → 综合工具认为 Q **有时需要保持** → 推断锁存器
> - 在 `always @(posedge CLK)` 中，`Q <= Q` → 触发器本身就能保持值，**不可能产生锁存器**
>
> 因此，**判断是否会产生 latch 的关键不是有没有 else，而是 always 块的敏感信号列表**：组合逻辑块（`@(*)`）中缺少 else 才会推断锁存器，时序块（`@(posedge CLK)`）中缺少 else 只是利用触发器的天然保持功能。
