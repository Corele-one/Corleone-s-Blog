# 怎么读代码？

> 与其痛苦地逐行阅读，不如让 AI 为你生成结构化的 Tutorial。

## 核心洞察

**读代码的本质不是"看懂每一行"，而是建立三层理解：**

```
第 1 层：架构全景 — 系统由哪些模块组成？数据怎么流动？
第 2 层：关键路径 — 核心算法/优化在哪个文件的哪个函数？
第 3 层：实现细节 — 具体的代码行做了什么？为什么这样做？
```

传统的代码阅读方式是"从头到尾逐行读"，这在大型项目中极其低效。更好的方式是：

1. **先建立全景图**（第 1 层），知道要看什么
2. **再聚焦关键路径**（第 2 层），知道重点在哪
3. **最后深入细节**（第 3 层），知道怎么实现的

## 邪修方法论：让 AI 当你的代码导游

### 为什么 AI 写 Tutorial 比自己读更高效？

| 维度 | 自己读代码 | AI 生成 Tutorial |
|------|-----------|-----------------|
| 速度 | 几天到几周 | 几分钟到几小时 |
| 全景图 | 需要自己拼凑 | AI 自动建立 |
| 关键路径 | 容易迷失在细节中 | AI 已经帮你筛选 |
| 前置知识 | 需要自己补齐 | AI 在 tutorial 中补 |
| 可复用性 | 只在脑子里 | 写成文档随时回顾 |

### 关键在于：分阶段，不要一次做完

最自然的读法是"先把所有代码都读完再写"，但这样效率很低。更好的方式是：

1. **Phase 1：全景扫描** — 让 AI 读整个项目，生成 index + 多章节结构
2. **Phase 2：深度拆解** — 对核心函数逐段拆解，带代码注释和流程图
3. **Phase 3：对比分析** — 对比不同方案的实现差异和 trade-off
4. **Phase 4：动手实践** — 生成 Build & Run 指南，自己跑一遍验证理解
5. **Phase 5：Research Insight 提炼** — 从学习过程提炼洞察，写成 Obsidian 笔记

每个阶段的产出都是下一个阶段的输入。这样做的好处是：你永远知道自己在什么层次上理解了什么，不会"读了很多但说不出重点"。

## Tutorial 生成 Prompt 模板

### Prompt 1：全景扫描（Phase 1）

```
这是 [项目名] 的 repo。我的相关背景是 [你的背景]。
项目文件夹下的内容为我生成结构化的 tutorial，帮助我读懂这一小项目的代码。

要求：
1. 先读完整个项目的所有文件，建立全景图
2. 以 markdown 格式输出，采用 index + 多章节的形式
3. 第一章必须是"环境与架构"，介绍项目整体结构，并告诉我怎么运行该项目，具体到repo中的文件
4. 每章末尾有"下一步"指引，链接到相关章节
5. 代码引用要标注具体文件路径和行号
6. 用 callout（> [!note]）标注重要概念
```

### Prompt 2：深度拆解（Phase 2）

```
基于你对 [项目名] 的理解，对 [具体文件/函数] 做逐段拆解：

1. 从函数签名开始，解释每个参数的含义
2. 画出整体流程图（伪代码形式）
3. 按逻辑段落拆分，每段包含：
   - 原始代码块（带行号注释）
   - 逐行/逐段解释
   - 为什么要这样写（设计意图）
   - 与其他部分的关联
4. 最后给出性能 profile 表，标注各阶段使用的硬件
```

### Prompt 3：对比分析（Phase 3）

```
对比 [方案A] 和 [方案B] 的实现差异：

1. 用表格列出关键维度的对比（数据格式、计算路径、精度、性能）
2. 画出两条数据流的对比图
3. 分析各自的适用场景和 trade-off
4. 指出代码中控制分支切换的开关（CMake 参数、运行时 flag 等）
```

### Prompt 4：动手实践（Phase 4）

```
为 [项目名] 生成一份 Build & Run 指南：

1. 前置条件清单（SDK、NDK、设备等）
2. 逐步的构建命令（带注释）
3. 部署到设备的命令
4. 运行 benchmark 的命令和参数说明
5. 结果解析的命令
6. 常见问题 FAQ
```

### Prompt 5：Research Insight 提炼（Phase 5）

```
基于我对 [项目/论文] 的学习过程，帮我整理一个 Research Insight：

1. 我的核心问题是什么
2. 我找到了什么答案
3. 这个答案与我已有的知识有什么联系
4. 还有什么没解决的问题
5. 下一步可以探索什么方向

格式：Obsidian markdown，带 frontmatter tags，使用 wikilink 链接相关笔记。
```

## 相关 Skill 推荐

### Obsidian 插件

| 插件 | 用途 |
|------|------|
| [CodeStyler](https://github.com/Emile-Bergem/obsidian-code-styler) | 代码块高亮美化，让 tutorial 中的代码更易读 |
| [Admonition](https://github.com/valentine195/obsidian-admonition) | callout 样式（`> [!note]`），tutorial 中标注重点 |
| [Git History](https://github.com/denolehov/obsidian-git) | 追踪 tutorial 文件的修改历史 |
| [Dataview](https://github.com/blacksmithgu/obsidian-dataview) | 查询所有 tutorial 的状态（哪些完成了、哪些在草稿） |
| [Excalidraw](https://github.com/zsviczian/obsidian-excalidraw-plugin) | 画架构图、数据流图，配合 tutorial 使用 |

### AI 工具

| 工具 | 用途 |
|------|------|
| **Claude + Extended Thinking** | 复杂代码分析，让 AI 先"想清楚"再输出 |
| **Cursor / Copilot** | IDE 内的代码解释，选中代码直接 ask |
| **Aider** | 命令行 AI 编程，适合边读边改 |
| **repomix** | 把整个 repo 打包成一个文件喂给 AI，解决上下文长度问题 |
| **gitingest** | 类似 repomix，把 GitHub repo 转成可读文本 |
