# NPU架构再分析

![[HC2023 Qualcomm Hexagon NPU_04.png]]

三个浅蓝色的块为计算单元，用于执行3种类别指令
1. Scalar：标量指令，作为控制流和通用计算
2. Vector：向量指令，用于执行数据并行的通用计算
3. Tensor：矩阵单元，用于矩阵计算和卷积、逐通道缩放
- 能够在多个线程中使用共享内存

深蓝色模块是存储层级：I$ 是指令缓存，D$ 是标量数据缓存，L2 是容量更大的共享缓存，TCM 是紧耦合存储器。它们不做神经网络乘加，而是把指令、输入、权重和中间结果放在离计算单元更近的位置。

灰色的 Multi-thread 表示硬件多线程/线程资源管理。每个线程有自己的程序与线程本地寄存器；线程之间共享一致性内存，并用普通同步机制协调。它的价值是让一个线程等待数据或释放扩展时，其他线程仍能推进，从而提高利用率。

灰色的 DMA/BUS 表示直接存储器访问引擎和片上互连。DMA 可以在计算单元不逐字节参与的情况下，把数据在 DDR、SoC 其他模块、L2/TCM 之间批量搬运；BUS 提供连接路径。它们解决的是“送货”，不是“做乘法”。
# Vector单元

![[file-20260819211509315.png]]

HVX为向量计算单元,类似 CPU SIMD 扩展，但有着更宽的向量引擎。

![[file-20260824224313113.png|250]]

 - VLIW 资源：4 个计算槽、1 个 load 槽、1 个 store 槽；编译器可以把彼此独立的操作组合到同一长指令中。
- 寄存器：32 个向量寄存器和 4 个向量谓词寄存器。**谓词决定哪些 lane 真正生效。**
- **每个向量寄存器都是1024位的**

![[file-20260825221851367.png]]

- 计算：交叉 lane 操作、移位和乘法等可并行进行。
- 访存：可从 L2/DDR 或 TCM load/store；TCM 还支持高并行 scatter/gather，适合地址不连续的数据并行。
- 应用：最初服务图像处理，后来扩展到 DNN 等更多工作负载。
# Tensor单元

HMX把数据并行的基本单位从“一维向量”提升为二维、三维甚至四维数据块。它直接面向矩阵乘法与卷积的数据复用方式，因此能以更少的取数和控制开销完成大量乘加操作。(Tensor SIMD)

![[file-20260825171217600.png|350]]

内部通常让激活块与权重块进入阵列，产生更宽位宽的累加结果；转换、缩放和激活尽量融合，减少中间结果落地。

>激活函数:采用多项式拟合
>低精度:Per-Chanel Scaling
 
# 编程模型

## 线程模型

每个硬件线程都有自己的程序。程序通过 VLIW 暴露可预测的指令级并行，Scalar ISA 执行**控制流和串行计算**；**Vector/Tensor 是可以获取与释放的 SIMD 扩展资源**。线程持有扩展时，才能发出相应指令。

![[file-20260825172133139.png]]

 - Scalar、Vector、Tensor 分别有专用寄存器文件，避免所有操作挤在同一寄存器端口上。
- 寄存器是线程本地的；内存可能被多个线程共享。
- 线程之间看到一致的共享内存，但仍需要锁、屏障、原子操作等正常同步。‘一致性’不等于‘无需同步’。
- 多线程还能覆盖某些等待，但真正隐藏 DDR 长延迟的主角通常是预取和 DMA。

## 内存模型

| ------------- | ------------------------ | ------------ | -------------------------------------- |
| 寄存器           | 各自的 Scalar/Vector/Tensor | 硬件 + 编译器     | 最快、最小；保存正在计算的操作数和部分和                   |

### Cache和TCM的区别

Cache 是硬件自动管理：程序照常访问地址，命中则快，未命中则逐级取数。优点是编程简单，缺点是命中率和替换行为可能让延迟波动。TCM 则更像软件管理的片上 scratchpad：软件明确决定哪些 tile 在什么时候搬进去、放在哪里、何时覆盖。

因此把 TCM 称为“软件管理的缓存”。它更可扩展、带宽更高，并且只要排程正确就没有 cache miss，性能更加可预测。代价是编译器/运行时需要做分块、地址规划、DMA 编排和同步。
# Efficiency

## 数据局部性

矩阵乘法 C=A×B 中，A 和 B 各有 N² 个元素，而计算包含约 N³ 次乘加。只要每个已读入的数据元素被复用约 N 次，就能让计算量相对数据搬运量显著放大。这是设置专用 Tensor/Matrix 引擎的最主要原因之一。

卷积还利用输入激活复用：一个带 halo 的输入区域可服务同一硬件输出张量中的多个输出点。软件应把数据整理成硬件 Tensor SIMD 期望的连续块；连续访问才能把每次内存传输的有效带宽用满。

![[file-20260825195858634.png|300]]

## 数值格式:浮点、定点和累加

在高吞吐 Tensor 硬件里，大量乘加器本身的面积和能耗成为主要成本，因此每一位是否值得都很重要。对于近似正态分布的数据，Slides强调：精度（有效位）往往比很宽的指数范围更重要。若经过合适的信噪比缩放，超过约 2-bit 的指数不一定带来更高准确率，反而可能挤占尾数。

![[file-20260825200622600.png]]

 - 简单整数/定点在给定准确率下通常成本最低。
- 浮点乘积若转为定点或 Kulisch 风格的精确累加，可在小指数位宽下减少开销并避免中间舍入。
 - CNN 数据通常更接近正态分布，演讲中的实验显示 INT8 在多项 PTQ/QAT 结果上优于 FP8 E4。
- Transformer 因 softmax 等机制出现离群值，但 QAT 可在训练中主动收敛/拉回离群值。
 - Hexagon 同时保留多种定点组合（A16W16、A16W8、A8W8、A8W4）和 FP16×FP16，以适应不同数据。

## 位宽对速度、能效、容量的影响

![[file-20260825201320064.png|400]]

| **变化**      | **直接结果**    | **进一步效果**            |
| ----------- | ----------- | -------------------- |
| 权重 16→8 bit | 权重容量/带宽约减半  | 同一 TCM 可容纳更多权重 tile  |
| 激活 16→8 bit | 激活容量/带宽约减半  | 更少 DDR 往返，更大的空间局部性   |
| 两侧同时减半      | 乘法器与数据通路都变窄 | 矩阵/卷积吞吐和能效可能获得叠加收益   |
| 位宽过低        | 量化误差上升      | 需要校准、混合精度、PTQ/QAT 补偿 |
